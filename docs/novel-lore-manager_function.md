## 0. 読み方と状態定義

- **[明示]**：開発者が現在までに明確に希望・採用候補として提示した機能。
- **[具体化]**：明示された機能を実際に使えるものにするため必要と考えられる操作・内部機能。要求定義時に承認が必要。
- **[提案]**：作家・編集者・開発者の視点で追加する検討候補。採用未決定。
- **[未決定]**：実現方式、UI、データ構造、範囲などをまだ決めていないもの。
- **[対象外]**：現状、製品目的から外しているもの。

**「100%」は構想として想定される機能を広く集めたことを表す呼称であり、網羅性の保証、実装率、完成度、採用決定を意味しない。**  
本書は市場調査前の機能台帳であり、実装優先順位・MVP境界・工数を確定しない。

## 1. 製品の位置づけ・決定済みの前提

1. **目的**：作者が作成したキャラクター・世界観・国・組織・物語事項・ルビ・伏線などの設定を保存、整理、素早く参照する。
2. **非目的**：小説本文を書くための執筆エディタの置き換えではない。
3. **プラットフォーム**：Windowsのデスクトップアプリ。スマートフォンアプリは対象外。
4. **利用場面**：小説家になろう、カクヨム、アルファポリスなどで執筆する際、別ウィンドウや別画面で設定を確認する。1画面/2画面のどちらに最適化するかは未決定。
5. **ファイル**：利用者のローカルにある `.md`・`.txt` を取り込み、読みやすく表示する。アプリ内で設定を新規登録し、編集・追加・削除・保存できる。
6. **テンプレート**：設定登録に使える最低限のフォーマットを用意する方針。項目構成は未決定。
7. **データ管理**：原則ローカル完結。ユーザーの作品・未公開設定を、同意なくクラウド送信しない。
8. **利用者**：AI非利用者とAIを創作に使う利用者の両方。AI機能は任意に分離し、非AI利用を妨げない。
9. **DB/開発技術**：SQLiteが第一候補。過去の「PostgreSQLを使う／Dockerを使う」という記述より、直近の「両者を基本構成から外す」という方針を優先する。UIフレームワーク、LLM、RAG、MCPは未選定。
10. **デザイン**：以前のComplete Shelf参考デザインは**廃止**。画面構成・UI・UXはユーザー調査後に再決定する。
11. **開発**：Windows環境、GitHubによる管理、Codexの活用を想定。
12. **頒布**：BOOTH／Microsoft Storeで100円程度のベータ提供は価格仮説。販売時期・ストア要件・実際の価格は未決定。

### 想定利用者の重要な違い

| 区分 | 想定ニーズ | 確認すべき点 |
|---|---|---|
| AI不使用の作者 | 手動登録、原文表示、検索、関係・履歴確認 | AIが裏で自動動作しない保証 |
| AI利用経験のある作者 | AI由来の設定も自分で登録・保存・検索 | 元資料とAI回答の区別、利用履歴 |
| 長編・群像劇の作者 | 膨大な設定、伏線、人物関係、時系列 | 情報量・検索性能・変更追跡 |
| 短編・設定の少ない作者 | 簡単な登録、最低限の検索 | 起動と導入の負担 |
| PC以外で執筆する作者 | Windowsを設定整理に使う可能性 | PC所有・使用頻度・端末間転送の必要性 |

## 4. AI利用規約と製品機能の関係

### 公式資料（2026-10-23確認）

- **小説家になろう**：https://syosetu.com/site/ai/  
  「AI直接使用」「AI間接利用」「AI補助的利用」「AI不使用」を区分。AI不使用は構想・プロット・執筆・校正のすべてでAIを使用していないことが条件。
- **カクヨム**：https://kakuyomu.jp/legal/guideline  
  「AI本文利用」「AI本文一部利用」「AI補助利用」のタグ付けを推奨。日常的な検索等に付随するAI補助機能はAI補助利用の例外として説明。
- **アルファポリス**：今回、AI利用に関する最新の運用区分を確定できていない。公開・配布前に一次資料を確認する。

### 機能設計上の基本方針

1. **非AI機能**：資料の手動登録、CRUD、ツリー、通常の全文検索、手動の関係図、ルビ辞書などは生成AIを呼び出さずに動かす。
2. **AI機能**：ローカルLLM・RAG等は別の任意モードとする。原文検索とAI生成による説明を混ぜない。
3. **境界の明示**：AIによる資料の検索・説明でも、投稿先のAI区分を本製品が保証することはできない。
4. **創作生成との分離**：AIが新しい本文・キャラ案・プロット案を生成する機能は、現状の製品目的の対象外。
5. **利用規約の変化**：公開前・アップデート時に公式ガイドラインとコンテストの応募規約を再確認する。

## 7. 作家・編集者視点の確認事項（市場調査用）

以下は**課題仮説**であり、一般の作家に実証された需要とは限らない。

- 執筆中に登場人物の別名・容姿・所属をすぐ確認したい。
- 過去の伏線と回収予定を思い出したい。
- 長編化により、世界観設定が複数の `.md` / `.txt` に散らばっている。
- 自分で決めた読み方・ルビを探したい。
- 設定が上書きされ、どれが最新なのか分からない。
- 登場人物が「いつ」「何を知っていたか」を誤りたくない。
- 未公開設定を外部に送信したくない。
- 既存の執筆ツールは維持したまま、設定確認だけ補完したい。

調査では、Nola、秀丸、OneNote、Notion、Obsidian、VS Code等との比較が必要。  
現時点で個別機能への利用者需要・市場規模・販売価格の妥当性は未確定。
