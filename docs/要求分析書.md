小説設定リファレンス・マネージャー

要求分析書 v0.1

作成時点：2026年9月

1.  要求分析の目的

本要求分析では、Windows向け小説設定管理デスクトップアプリについて、

誰を対象とするか

ユーザーは何に困っているか

どの場面で利用するか

何を最優先で解決するか

既存ツールでは何が不足しているか

AI利用者・非AI利用者の双方をどう扱うか

どの機能をMVPへ含めるべきか

を整理する。

この段階では具体的なDBテーブル、API、LLMモデル等は確定しない。

2.  プロダクトの目的

本システムの目的は、

小説執筆者が過去に自分で決めた設定を探すために、本文執筆を中断する時間を減らすこと

である。

本文を書くエディタではなく、

設定を保存・整理・検索・確認するための補助デスクトップアプリ

として位置付ける。

中心となる利用価値は、

「あれ、何だったっけ？」

を数秒で解決することである。

3.  対象ユーザー

3.1 Primary User A

AIを使用しない小説執筆者

特徴：

キャラクターを自分で考える

世界観を自分で考える

プロットを自分で考える

本文も自分で執筆する

生成AIを創作工程へ使用したくない

主な要求：

AIなしで設定を管理したい

高速に検索したい

ルビを確認したい

キャラクターや国家の関係を確認したい

世界設定を整理したい

3.2 Primary User B

AI補助を利用する小説執筆者

特徴：

AIで設定案を整理することがある

AIで資料整理・検索等を行う

自分で本文を書く場合もある

AI利用範囲を意識している

主な要求：

通常検索とAI検索を分離したい

AIが使われた機能を把握したい

自分の設定のみをRAGで検索したい

外部AIで作成したMarkdown/TXTも管理したい

3.3 Primary User C

長編・世界観重視型作家

対象例：

異世界ファンタジー

VRMMO

SF

歴史

群像劇

長期シリーズ

特徴：

設定数が多く、

国家

組織

地域

能力

武器

時系列

伏線

などの関連が複雑になる。

本システムとの適合度が最も高いユーザー層と想定する。

4.  現時点では対象外とするユーザー

初期開発では以下を対象外とする。

スマートフォンのみで執筆するユーザー

タブレットのみで執筆するユーザー

チーム共同執筆を目的とするユーザー

本文生成AIを求めるユーザー

小説投稿機能を求めるユーザー

完全クラウド型の執筆環境を求めるユーザー

なお、「小説執筆者のPC・スマートフォン・タブレット利用比率」について、2026年現在の日本のWeb小説作者全体を代表できる十分な統計は今回確認できていない。

したがって、

「作家はPC利用者が多いからWindowsにする」のではなく、「今回解決対象をPC執筆中の設定参照に限定するためWindowsにする」

と定義する。

5.  実際の作家から確認できる課題

2026年のObsidian利用者では、

Characters

Locations

Powers

Story

Arc

などをフォルダ、タグ、リンク等で整理している例が確認できる。

一方、

さらに2026年9月のWorldbuilding利用者では、

したがって、本システムが扱うべき問題は単純な「メモ保存」ではない。

保存した情報を再発見できない問題

が重要である。

6.  既存アプリから確認できる課題

6.1 動作速度

ストーリープロッターのApp
Storeレビューでは、機能そのものを高く評価しながら、

プロット表示に約10秒

キャラクター表示にさらに10～20秒

操作時に止まる

という動作速度に関する不満が投稿されている。

個別レビューであり全利用者を代表するものではないが、本システムが「高速性」を重要要求とする根拠の一つになる。

6.2 保存信頼性

Nolaのレビューでは、

キャラクター設定

世界観

ルビ

などの機能は評価されている一方、自動保存がなく、設定入力中にアプリが終了して入力内容を失ったという利用者の報告が存在する。

したがって、

Auto Save・データ保護は単なる便利機能ではなく要求事項

として扱う。

UR-02

ユーザーは、どこに保存したか覚えていなくても設定を発見できること。

UR-03

ユーザーは、設定確認のために本文執筆画面から大きく離れる必要がないこと。

UR-04

UR-06

11. AI規約から生じる要求

小説家になろうでは2026年現在、作品のAI利用状況設定が必須であり、

AI直接使用

AI間接利用

AI補助的利用

AI不使用

が定義されている。

AI補助的利用には、AIによるアイデア出し、資料調査、誤字脱字確認等が含まれる。

AI不使用は、構想・プロット・執筆・校正の全工程で一切AIを使用していない場合と定義されている。

また、2026年9月以降、過去作品についてもAI利用状況が未設定の場合、エピソード投稿・編集等の一部操作が制限されている。

カクヨムでは、

AI本文利用

AI本文一部利用

AI補助利用

の目安が提示されている。

AIのアイデアや資料をもとに作者本人が本文を書くケースもAI補助利用に含まれる。一方、日常的な検索サービスのAI補助やドキュメントソフトの自動校正については対象外としている。

したがって要求として、

AR-01

本システムは特定投稿サイト上のAI利用区分を自動判定しない。

AR-02

生成AIを使用する機能は明確に識別できること。

AR-03

生成AIを完全に無効化した状態でも主要機能を利用できること。

AR-04

外部からImportされた設定ファイルがAI生成物であるかを勝手に推定しないこと。

AR-05

アプリから「この使用方法ならAI不使用扱いになる」と保証しないこと。

したがって、

完全自由型ではなく、標準テンプレート＋カスタマイズ

15. データ安全性要求

DR-02

Auto SaveによってUI操作を停止させない。

DR-03

外部Markdown/TXTの原本を不用意に上書きしない。

DR-04

Export / Backup手段を用意する。

DR-05

アプリ異常終了時のデータ損失を最小化する。

16. 性能要求

速度は本システムの重要な差別化要因とする。

既存ツールでは設定画面表示まで10～20秒かかったという利用者レビューも存在するため、同様のUXを避ける。

初期目標値：

Quick Recall Window表示 500ms以内を目標

通常検索 500ms以内を目標

Wiki設定表示 500ms以内を目標

1,000件程度の設定検索 1秒以内を目標

ただしこれは現時点では性能目標であり、要件定義・実装後のベンチマークで再調整する。

37. 要求分析結果

現時点で最も強く確認できる問題は、

「設定を作れない」ことではなく「既に作った設定を整理・再発見することが難しい」

ことである。

既存ツールには多機能なものが存在するが、利用者から、

情報が散乱する

古い設定を忘れる

設定変更の影響箇所を探すのが難しい

操作が重い

保存に不安がある

という課題が確認できる。

したがって本システムは、

小説の制作そのものではなく、制作中の「設定Recall」を高速化する

ことへ集中する。

ことに特化する。
