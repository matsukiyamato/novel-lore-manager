| 記号 | 意味 |

| `PROVISIONAL` | モックアップを進めるための提案・仮仕様。未承認。 |

## 1. 製品の目的・非目的

### 1.1 目的

小説家が、登場人物、世界観、地名・地域、組織、設定用語、過去の出来事などの設定資料を**作成・管理・編集・検索・素早く参照**できるWindowsデスクトップアプリを目指す。`.md`／`.txt` で分散管理されている既存資料を取り込み、執筆の集中をできるだけ中断せず必要情報へ到達できることを重視する。

### 1.2 対象ユーザー

- 小説家になろう、カクヨム、アルファポリス等で執筆する作家。
- 執筆前に設定を作り込む人、執筆しながら設定を増やす人、既存の大量のテキスト資料を持つ人。
- 一画面切替、並列ウィンドウ、デュアルモニターでの利用を想定する。

### 1.3 非目的

- **小説本文を執筆するための本文エディタではない。**
- モックアップ段階で本番用DB、クラウド同期、AI/RAG/MCP、実ファイルへの自動書き込みは作らない。
- VS Codeの見た目やコードをコピーすることではなく、機能的なワークベンチの操作原則を参考にする。

## 2. 製品とモックアップのスコープ

| 領域 | 最終的な製品方針 | 今回のモックアップ |
|---|---|---|
| 配布 | Windowsデスクトップアプリ | ブラウザで動くローカル試作。技術選定を固定しない |
| 設定資料 | `.md/.txt`を整理・編集 | 同じ架空資料をメモリ上で操作・疑似保存 |
| 作品 | 作品ごとに独立管理 | 作品選択・作成・切替を模擬 |
| 検索 | 作品全体・現在資料、別名やルビ、分類絞り込み | モックデータで挙動を試す。高度な日本語正規化の本番精度を保証しない |
| Quick Recall | 独立小窓、ショートカット起動、最前面、メインを閉じても利用 | 別ウィンドウまたは明示された模擬ウィンドウ。OS全体の動作は対象外 |
| 保存 | `Ctrl+S`による手動保存が基本 | JSのメモリ上で保存済み／未保存／Undoを再現 |
| 取り込み | コピーまたは直接編集を選択 | 選択UIと警告・結果を模擬。外部ファイルを書き換えない |
| デザイン | 森・童話・直観性・長時間可読性 | 3テーマを同一機能で比較 |
| AI | 非AIでもコア機能を完結 | 初期UIにAI機能を表示しない |

## 3. 機能要件：作品と資料管理

- `FR-001` `CONFIRMED / MOCK`：作品の新規作成・選択。初期の作品切替は作品選択画面へ戻る。
- `FR-002` `CONFIRMED`：作品データは原則独立。複数作品の同時オープンや横断検索は初期対象外。
- `FR-003` `CONFIRMED / OPEN`：他作品への資料移動・コピーを希望するが初期実装順序は未決。資料共有は `FUTURE`。
- `FR-004` `CONFIRMED / MOCK`：フォルダとカテゴリの両方から資料にアクセスできる。フォルダとカテゴリの実データは混同しない。
- `FR-005` `CONFIRMED / MOCK`：基本カテゴリに加え、ユーザー定義カテゴリを追加・編集できる方針。
- `FR-006` `CONFIRMED / MOCK`：資料の主カテゴリは1つ、タグは複数。
- `FR-007` `CONFIRMED / MOCK`：エクスプローラー風ツリー、複数タブ、左右分割で別資料を表示。
- `FR-008` `CONFIRMED / OPEN`：ユーザーがパネルを自由配置できることを目標とする。初回プロトタイプではサイドバー開閉・幅調整から段階的に再現してよいが、対応範囲を明記。
- `FR-009` `CONFIRMED / OPEN`：同一作品内で同名ファイルを認めない方針。拡張子・文字正規化などの衝突判定は未決。
- `FR-010` `OPEN / PROVISIONAL`：資料ID、フォルダ位置、表示名の分離を推奨。1資料を複数ビューで参照するときの仕様は要承認。
- `FR-011` `CONFIRMED / MOCK`：人物・世界観・組織などのMarkdownテンプレート、およびユーザー定義テンプレート。

## 4. 機能要件：インポート・エクスポート

- `FR-101` `CONFIRMED / MOCK`：`.md`・`.txt`・フォルダの取り込み。
- `FR-102` `CONFIRMED / MOCK`：取り込み時に「元のフォルダ階層維持」か「カテゴリ別整理」を選べる。
- `FR-103` `CONFIRMED / MOCK`：コピー管理か元ファイル直接編集かを、ユーザーが一括選択する。全対象への影響を画面で説明する。
- `FR-104` `OPEN`：その選択の適用単位が「今回の取り込み一括」か「作品全体」か未決。モックでは取り込みバッチ単位を仮置きする。
- `FR-105` `CONFIRMED / OPEN`：原文を保持し、`.txt`もMarkdown用画面に統一表示したい。実ファイルを`.md`に変換するかは未決。
- `FR-106` `PROVISIONAL / MOCK`：選択→プレビュー→管理方式と配置の確認→実行結果という取り込みウィザード。
- `FR-107` `OPEN`：見出し解析による目次生成は非AIで検討可能。意味的な人物名・地名の自動抽出は精度検証が必要で必須実装を確約しない。
- `FR-108` `CONFIRMED / OPEN`：ユーザーが明示操作で内容更新できるようにしたい。「再読み込み」と「書き戻し／同期」は仕様を分けて検討。
- `FR-109` `CONFIRMED`：ファイル単位（md/txt）、フォルダ構造、ZIPによる出力を目標とする。モックでは手順のみ再現可。
- `FR-110` `OPEN / FUTURE`：外部変更との自動同期・競合解決は初期範囲外。

## 5. 機能要件：Markdown編集・保存・削除

- `FR-201` `CONFIRMED / MOCK`：ソース編集、プレビュー、左右分割を切り替えられる。
- `FR-202` `CONFIRMED / MOCK`：`Ctrl+S`による明示的な手動保存が基本。継続的な自動保存は未採用／`OPEN`。
- `FR-203` `CONFIRMED / MOCK`：`Ctrl+Z`と画面上のUndoボタンを用意する。
- `FR-204` `PROVISIONAL / MOCK`：未保存時のタブ閉鎖・作品切替・終了では、保存・破棄・キャンセルを選ぶ確認を出す。
- `FR-205` `OPEN`：保存履歴・バージョン復元・クラッシュ復旧用一時データの詳細方式は未決。
- `FR-206` `CONFIRMED / MOCK`：ゴミ箱への移動・復元・アーカイブは異なる状態として扱う。
- `FR-207` `CONFIRMED / OPEN`：削除済み資料が存在することをグレーアウト等で視認できるようにする。通常ツリーへの表示条件・完全削除方式は未決。

## 6. 機能要件：検索・関連リンク

- `FR-301` `CONFIRMED / MOCK`：デフォルトは選択作品の全資料検索。現在の資料だけにも切替可能。作品横断検索は `FUTURE`。
- `FR-302` `CONFIRMED / OPEN`：部分一致、名前・別名・通称、ひらがな／カタカナ、漢字の表記ゆれ、ルビ・読み検索を目指す。モックでの実現レベルを明記し、万能な自動表記ゆれ解決を保証しない。
- `FR-303` `CONFIRMED / MOCK`：カテゴリ・タグ・フォルダで絞り込み。
- `FR-304` `CONFIRMED / MOCK`：結果一覧＋本文抜粋＋プレビュー＋一致箇所強調。
- `FR-305` `CONFIRMED / MOCK`：デフォルトは関連度順。ソートメニューから変更可能。具体的な選択肢は仮仕様として明記。
- `FR-306` `CONFIRMED / OPEN`：手動リンクと `[[資料名]]` 風の記法を候補とする。リンクの安定識別・名称変更時処理は未決。
- `FR-307` `OPEN`：非AIでの関連候補提示は検証してから範囲を確定。
- `FR-308` `FUTURE`：自然言語検索、LLM、RAG、矛盾チェックなどは初期モックの対象外。

## 7. 機能要件：Quick Recall

- `FR-401` `CONFIRMED / MOCK`：メイン画面と独立する小型参照ウィンドウ。初期ワイヤーフレームの大きさ約420×560pxは**仮値**。
- `FR-402` `CONFIRMED / OPEN`：ショートカット起動、メイン画面を閉じても利用できる最終製品を目指す。ブラウザ試作ではOSグローバルショートカット不可。トレイ／ボタン起動は将来追加候補。
- `FR-403` `CONFIRMED / OPEN`：常に最前面を希望、邪魔なら最小化。ブラウザでは保証できないため模擬表現と明記。
- `FR-404` `CONFIRMED / OPEN / MOCK`：概要を先に見せ、詳細・全文表示を切り替える。初期表示するフィールドは暫定。
- `FR-405` `CONFIRMED / OPEN / MOCK`：閲覧だけでなく必要に応じた本文編集・執筆中の簡易メモも希望。表示と保存の分離は仮仕様。
- `FR-406` `OPEN`：メイン画面との同時編集・競合・メモの永続化を要設計。モックでは共有ドラフトと別メモを仮置きできる。
- `FR-407` `OPEN`：ウィンドウ位置、フォーカス、マルチモニター、前面固定、ホットキー衝突はネイティブ実装前に検証する。

## 10. 3つのUIテーマの比較要件

**テーマ間で機能、DOMの意味構造、サンプルデータ、表示条件、ナビゲーション、操作手順、画面サイズを同一にする。** テーマは原則CSSのデザイントークンと装飾ルールを変更する。見やすさに直結するレイアウト差異を試したい場合は、テーマ比較とは別実験として管理する。

| テーマ | 表現の主軸 | 検証したいこと |
|---|---|---|
| `Forest Workbench` | 深緑／チャコール／森の書斎、作業密度重視 | 集中、情報の見つけやすさ、長期使用感 |
| `Storybook Atelier` | 羊皮紙／セピア／古書の温かみ、装飾を節制 | 世界観と可読性の両立 |
| `Quiet Lore Studio` | セージグリーン／オフホワイト、控えめなモダンUI | 直感性、明快さ、アクセシビリティ |

共通の比較基準（初期仮案）：Markdown可読性25%、操作の直感性25%、情報発見20%、長時間適性20%、世界観10%。この比率はユーザー調査の実測結果ではない。

## 11. モックアップの技術・ファイル管理要件

### 11.1 技術

- `HTML5`、`CSS3`、`Vanilla JavaScript (ES Modules)`。
- 原則としてReact、Vue、Angular、TypeScript、Tailwind、フロントエンドフレームワークを**今回の制作に導入しない**。
- 本番バックエンド、DB、Docker、RAG、MCP、LLM、外部APIへの接続を作らない。
- サンプルデータはローカルのJSオブジェクトなどに保存。試作の操作は仮状態の更新で再現し、ユーザーの本物のファイルを変更しない。
- JavaScriptモジュールは`file://` ではなく `http://127.0.0.1` 等のローカルHTTPサーバーで検証する。
- Markdownプレビューでは任意HTMLやJSを実行させず、エスケープまたは安全な限定表現で実装する。

### 11.2 管理境界

- Gitの現在の**既存モックアップブランチ**で作業し、勝手に `main` へ切り替え・マージしない。
- 新規実装は原則 `mockups/novel-lore-manager/` 以下。既存アプリと本番データを触らない。
- リポジトリ内で既存の設計書や `AGENTS.md` が存在する場合は上書きせず、差分・矛盾を報告。
- Skillは外部の作業指針。Skillのインストール結果やGit追跡対象の扱いは別途レビューし、無断でmainへマージしない。

## 12. Codex CLIとSkillの役割・工程

> Skillは独立した実装エージェントではない。Codexが**実際に導入された**Skillの `SKILL.md` を読んで、該当する作業で適用する。存在しないSkill・検索結果の利用を報告してはならない。

### `UI UX Pro Max`：調査と一貫性

- 実際のSkillパス、`SKILL.md`、検索スクリプトと `--help` を確認する。
- 専用の検索機能が使える場合は `--design-system`、`--domain ux`、`--domain typography`、`--domain color`、`--domain icons` 等でデスクトップ用途に適した候補を探す。
- 採用するルール、採用しないルール、要件との整合・出典（実行コマンドや得られた候補）を成果物に記す。
- LP、SaaS営業用、モバイル用のパターンを無条件で採用しない。検索が失敗したら未検証として報告する。

### `frontend-design`：テーマ固有の視覚表現

- 実際の `SKILL.md` を読み、テーマごとに配色・タイポグラフィ・質感・特徴・避ける表現を計画する。
- 単純な色替えに留めず、**機能とレイアウトを保ったまま**3つの美術的方向性を差別化する。
- 実装した画面の批評を行い、日本語可読性やデスクトップ操作性を損なう装飾は修正する。

### Codex CLI：作業の調整・実装・検証

- 設計資料、AGENTS.md、実際のSkill構成を確認する。
- 共通HTML・3テーマCSS・JSによる画面遷移／模擬操作を実装する。
- 同一テスト条件の画像比較、動作検証、変更差分と既知の制約を報告する。

## 14. 未決事項（承認待ちのデータ管理ルール）

`data-management-design.md` の `DM-Q01`〜`DM-Q08` は**提案があるだけで、ユーザーによる最終承認はまだない**。

| ID | 論点 | モックでの暫定取扱い |
|---|---|---|
| `DM-Q01` | 同じ資料の複数ビュー参照 | 1つの論理IDを参照する案 |
| `DM-Q02` | 同名禁止の具体的な範囲 | 作品内ファイル名の衝突警告を模擬 |
| `DM-Q03` | コピー／直接編集の適用単位 | 取り込みバッチ単位の仮選択 |
| `DM-Q04` | TXTの形式と保存 | 原形式保持＋Markdown画面で編集する仮表示 |
| `DM-Q05` | 更新操作 | 「再読み込み」と「書き出し」を別ラベルで表示 |
