## 0. 本書の読み方

- **確定方針**：ユーザーが実現したいと明示した事項。具体的な内部実装まで決まった意味ではない。
- **暫定案**：モックアップを進めるための提案。ユーザーによる最終承認は未了。
- **未決**：仕様選択・実現性の確認が必要な事項。
- **将来候補**：初期モックアップ／初期実装に含めず、後から検討する事項。

本書は**製品としての目標要件**と**今回のプロトタイプで再現する範囲**を分ける。特に「実際のファイルを変更する」「OS全体のショートカットを登録する」「常時最前面で動かす」は、ブラウザモックだけで実現済みとは扱わない。

## 1. 製品概要

### 1.1 目的と位置づけ

Novel Lore Managerは、小説家が**人物・世界観・地理・組織・用語・出来事などの設定資料を作成、整理、編集、検索、参照するための専用Windowsデスクトップアプリ**である。小説本文の執筆エディタではない。執筆中に必要な設定をすぐ取り出し、創作の集中を妨げないことを中心価値とする。

### 1.2 対象ユーザーと利用シーン

- 「小説家になろう」「カクヨム」「アルファポリス」などの小説投稿者。
- 執筆前に設定を作り込む人／執筆しながら設定を追加する人／既存の `.md`・`.txt` を整理したい人。
- 1画面でウィンドウを切り替える、左右に並べる、デュアルモニターで使う、いずれも想定する。
- Quick Recallでよく確認したい情報の仮説上の優先順は、**過去の設定・出来事 → 人物情報 → 矛盾の確認 → 地理・世界観**。実ユーザー調査で検証する。

### 1.3 基本原則

1. 設定資料の管理と執筆支援に集中し、本文執筆ツールにしない。
2. 通常の設定管理・編集・検索・参照はネットワークなしで動作する。
3. Windowsらしいタブ、ツリー、分割表示、ショートカットの操作感を参考にする。ただしVS Codeを複製しない。
4. 作業領域の可読性と安全性を、童話・森の装飾より優先する。
5. AIは必須にせず、非AIモードで基本作業が完結する。

## 2. 対象範囲と非対象

### 2.1 今回のUI/UXプロトタイプで扱う範囲

- 作品選択／作品作成、資料ツリーとカテゴリ切り替え。
- Markdownの編集・プレビュー・左右分割、複数タブ、資料の分割表示。
- 作品内検索、ヒット箇所の強調、プレビュー、絞り込み・並び替えのUI。
- `.md`／`.txt` の取り込みウィザード（ファイル実操作はモックでも可）。
- Quick Recallの独立小型ウィンドウ相当の操作体験。
- 手動保存、Undo、ゴミ箱、アーカイブ、簡易メモの状態表現。
- 同じサンプルデータに対する3つのデザイン案の比較。

### 2.2 今回は実装不要／将来候補

- 実ファイルの破壊的変更、本番DB、同期・競合解決の完成実装。
- ローカルLLM／外部AI API／RAG／MCP、自然言語検索、AI矛盾検出。
- 複数作品横断検索、複数作品からの同一資料の共有。
- 自動バックアップ、高度な保存バージョン復元。
- ネイティブのOSグローバルショートカットや前面固定の完全再現（本実装で検証）。

## 4. UI/UX要件

### 4.1 操作構造

- 左側にエクスプローラー／カテゴリ、中央に編集・プレビュー、必要に応じて関連情報パネルを置く構造を初期案とする。
- 複数タブ、左右分割、自由なパネル配置を目標とする。自由配置の操作方法はプロトタイプで比較する。
- Quick Recallは通常ワークスペースとは別の操作密度にする。まず検索・閲覧を優先し、編集やメモは必要時に展開する**暫定案**。
- キーボードとマウスの双方で基本操作でき、選択・ホバー・フォーカス・未保存・削除などの状態を識別できるようにする。

## 7. 技術・設計上の留意点

1. **ファイル名と識別子**：同名禁止だけでは衝突・取り違えを完全に防げない。内部ID、実パス、表示名を分離して検討する。
2. **直接編集**：外部エディタとの同時変更や書き込み権限に注意。更新前検知、上書き確認、原本復旧方針が必要。
3. **MarkdownとTXT**：統一表示、実際の変換、元形式への書き戻しの3つを区別する。
4. **検索**：文字の正規化は実装可能な範囲を定義する。漢字の読み・表記ゆれの完全自動認識を約束しない。
5. **関連リンク**：`[[資料名]]` は独自構文の候補。資料名変更、削除、同名衝突への対処が必要。
6. **保存**：手動保存と、クラッシュ対策の一時復旧データは別設計。自動保存未採用でも事故対策は必要。
7. **Quick Recall**：メイン画面を閉じても動くための常駐方式、OSショートカット、最前面、編集競合はネイティブ実装時に要検証。
8. **ローカル構成**：過去に検討したFastAPI／PostgreSQL／Dockerなどは、本書では採用確定としない。Windows配布・軽量性を比較して選ぶ。
