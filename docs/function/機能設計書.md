## 1. 文書の目的と読み方

本書は、要件定義書 v1.0 の製品目標に、現行モックアップの画面・操作・制約を追記した機能設計書である。Novel Lore Managerは、人物・世界観・地理・組織・用語・出来事などの**設定資料**を管理、編集、検索、参照するアプリであり、小説本文の執筆エディタではない。通常の資料作業はオフラインで完結させることを製品目標とする。

| 軸 | 表記と意味 |
|---|---|
| 製品要件 | **確定方針**＝ユーザーが望む機能。**部分確定**＝方向はあるが詳細未決。**暫定案**＝モックを進めるための提案。**未決・要検証**＝判断または技術検証が必要。**将来候補**＝初期対象外。 |
| モック実装 | **実装**＝ブラウザ内の操作経路がある。**模擬**＝操作結果はページ内データだけに反映。**一部実装**＝必要な状態や復帰経路の一部がない。**未実装**＝操作・状態がない。**未検証**＝コード上の経路はあるが実ブラウザで確認していない。 |

「確定方針」は製品目標の合意であり、現行モックで完成したという意味ではない。逆に「模擬」の操作が成立しても、その仮の挙動が製品仕様として承認された意味にはならない。

### 1.1 対象とデータ境界

- 現行モックの起点は `mockups/novel-lore-manager/index.html`。HTML5、CSS3、Vanilla JavaScript（ES Modules）を使用する。`preview.mjs` による `127.0.0.1:4173` のローカル静的配信を前提とし、`file://` 起動は想定しない。
- 初期作品「灰冠の王国」には架空資料6件（人物3、世界観2、組織1）がある。新規作品・資料・編集・履歴・ルビ辞書・メモ・保管状態・取り込み結果はページのメモリ内にあり、再読み込みで初期化される。作品切替時は作品ごとの資料・タブ・選択状態を退避・復元する設計だが、ブラウザでの通し検証は未了。
- テーマ選択だけを `localStorage` の `nlm-theme` に保持する。「保存」「取り込み」「削除」「復元」は実ファイルやDBを変更しない。取り込み対象は名前と相対パスを参照し、本文は読み取らない。
- 対象JSに外部API呼び出しはない。ローカル配信、画面から開き得る通常のHTTP(S)リンク、外部API連携は別の概念である。AI機能の入口は初期モックに表示しない。
- ブラウザ小窓はWindowsの常時最前面、OS全域ショートカット、ネイティブ最小化、メイン終了後の常駐を保証しない。

## 3. 機能設計

### 3.1 作品・資料管理（FR-001～FR-011）

**製品目標**：作品の新規作成と独立管理、フォルダ階層とカテゴリ・複数タグ、複数タブと左右分割、標準・ユーザー定義テンプレートを提供する。別作品へのコピー／移動の優先順位、自由配置の範囲、同名判定、内部IDと保存先の関係は未決である。資料を複数作品で共有する仕組みは将来候補。

| 要件 | 現行モックの操作・状態 | 制約・残件 |
|---|---|---|
| FR-001/002 | 作品名・ジャンル・仮表紙を選んで作成する。作品名の空欄・重複を検査。最近開いた作品を `lastOpened` 順に最大3冊表示し、全作品を作品名検索、最近開いた順／作品名順で探せる。作品ごとの状態を退避・復元する設計。 | 作成・履歴はメモリ内。全作品0件の初期空状態はない。作品間の編集・取り込み・保管庫操作を含む通し検証は未了。 |
| FR-003 | 作品は個別に選択・作成できる。 | 別作品への資料コピー／移動は未実装。優先順位未決。 |
| FR-004～006 | 通常資料を固定フォルダ領域とカテゴリから開く。資料には検索対象の登録済みタグがある。 | 任意階層、カテゴリの追加・編集、タグ編集、主カテゴリ変更は未実装。製品要件では主カテゴリ1つ・タグ複数。 |
| FR-007/008 | 資料IDでタブを開閉し、別資料を右側に参照表示できる。区切りはポインターまたは左右キーで調整。 | 右側は参照表示。自由なパネル配置と配置の永続化はない。 |
| FR-009/010 | 新規資料名の空欄・同名を検査。内部で資料IDを使用。 | 製品としての同名判定単位、拡張子・大小文字・全半角、複数場所からの参照方式は未決。 |
| FR-011 | 最初の資料を資料名・カテゴリ・Markdown本文から作成できる。 | 標準Markdownテンプレートとユーザー定義テンプレートは未実装。 |

### 3.2 取り込み・表示・出力（FR-101～FR-110）

**製品目標**：`.md`／`.txt` とフォルダの取り込み、元階層保持／カテゴリ別整理、アプリ内コピー／元ファイル直接編集を選べるようにする。原文保持と統一表示を目指すが、`.txt` の画面表示、実変換、書き戻しは別の判断とする。`.md/.txt`、フォルダ構造、作品ZIPの出力は製品目標であり、現行モックの実ファイル出力を意味しない。

| 要件 | 現行モックの操作・状態 | 制約・残件 |
|---|---|---|
| FR-101/106 | ファイル・フォルダ選択、ドラッグ投入、サンプル2件を受け付ける。対象 → 管理方式 → 整理方式 → 確認 → 結果の5段階。 | `.md`／`.txt` の拡張子と同一パスの重複を判定。本文、文字コード、権限は確認しない。ウィザードの流れ自体は要件上の暫定案。 |
| FR-102/103 | COPY／DIRECTの想定と、元階層保持／カテゴリ別整理を選択単位で一括設定し、確認画面に示す。 | どのファイルも実際にはコピー・直接編集しない。「一括」が今回の取り込みか作品全体かは未決（FR-104）。 |
| FR-105 | 取り込み結果として資料名と固定ダミー本文を追加する。 | 原文保持、TXTの統一表示・変換・書き戻しは未実装。方式は未決。 |
| FR-107/108 | 限定Markdownのプレビューと見出し表示はある。 | 取り込み時の目次生成・意味抽出は検証項目。「更新」操作の意味は未決。 |
| FR-109/110 | エクスポートと自動同期はモック対象外。 | 出力方式は製品目標。元ファイルとの同期・競合処理は未決。 |

同名タイトル候補は現行モックで自動スキップされる。衝突ごとの選択や失敗からの復帰UIはなく、結果は失敗0件として表示される。この扱いを製品仕様として確定しない。

### 3.3 Markdown編集・保存・削除（FR-201～FR-207）

**製品目標**：Markdownの編集／プレビュー／左右分割、`Ctrl+S` による手動保存、`Ctrl+Z` と画面操作によるUndo、削除資料のゴミ箱への移動・復元、独立したアーカイブ状態を提供する。自動保存、履歴・クラッシュ復旧、削除資料のツリー表示範囲は未決。

| 要件 | 現行モックの操作・状態 | 制約・残件 |
|---|---|---|
| FR-201 | 編集／プレビュー／左右分割を切替。見出し1～6、引用、箇条書き、番号付きリスト、水平線、太字、斜体、インラインコード、HTTP(S)リンク、`[[資料名]]`、`｜語《読み》` を限定表示。生HTMLは文字として表示。Markdownガイドあり。 | 完全なMarkdown、画像、任意HTMLは対象外。資料リンクは表示名の完全一致で解決する仮実装。 |
| FR-202/203 | 入力本文と保存済み本文の差で未保存状態を表示。保存ボタン／`Ctrl+S` でメモリ内の保存済み本文を更新。資料ごとに最大100件の入力履歴を持ち、Undoボタン／編集欄の `Ctrl+Z` で戻す。 | ディスク保存、保存失敗、Redo、永続履歴、クラッシュ復旧はない。自動保存は未決。 |
| FR-204/205 | 未保存タブを閉じる際と作品画面へ戻る際に保存／破棄／キャンセルを提示する。戻る際は未保存資料全件を対象とする。 | 通常の左メニュー切替には同じ確認を通さない。ページ離脱警告はブラウザ依存。保存バージョン復元は未実装。 |
| FR-206/207 | 保管庫で通常／アーカイブ／ゴミ箱を分ける。移動前確認、未保存時の保存／破棄／キャンセル、通常状態への復元を模擬。 | 実削除・実移動・完全削除はしない。削除済み資料をツリー上でどうグレー表示するかは未決。 |

### 3.4 検索・リンク・ルビ（FR-301～FR-308）

**製品目標**：標準範囲は現在の作品全体とし、現在資料だけにも切り替える。部分一致、登録済み別名、読み仮名・ルビ、表記ゆれを扱いたいが、漢字の読み推定や一般的な表記ゆれの自動認識は技術検証が必要。結果一覧、本文プレビュー、抜粋と強調、カテゴリ・タグ・フォルダ絞り込み、関連度順と並び順変更を提供する。作品横断検索とAI検索は初期対象外。

| 要件 | 現行モックの操作・状態 | 制約・残件 |
|---|---|---|
| FR-301～303 | 通常資料の題名・明示した別名・タグ・本文を部分一致検索。NFKC正規化と日本語ロケールの小文字化を適用。全資料／現在資料、フォルダ → カテゴリ → タグの絞り込みを操作できる。 | 漢字の読み推定、一般的な表記ゆれ解決、作品横断検索はない。 |
| FR-304/305 | 件数、抜粋、簡易強調、結果プレビュー、資料を開く操作、0件表示と条件解除を用意。名前順／仮の関連度順を選べる。 | 強調は単純な文字位置処理。「関連度順」は実スコアではなく初期配列順。検索失敗の模擬経路はない。 |
| FR-306/307 | `[[資料名]]` 風リンクをプレビューで表示。 | リンクの識別、改名追従、リンク切れ処理、非AI関連候補提示は未実装／要検証。 |
| FR-308 | 自然言語検索、AIリンク・矛盾検出は将来候補。 | 初期モックにAIの入口は置かない。 |

追加のモック機能として、ルビ辞書に単語・読み・投稿先を登録し、一覧・検索・削除できる。編集欄では候補をTabまたはクリックで挿入する。辞書はメモリ内、投稿先別の表記は仮例であり、正式な変換・出力ではない。

### 3.5 Quick Recall（FR-401～FR-407）

**製品目標**：通常ワークスペースと独立した小型ウィンドウをショートカットで呼び出し、検索・概要参照、必要に応じた詳細・編集・簡易メモを行う。メインを閉じた後の稼働、常時最前面、ウィンドウ位置、複数モニター、フォーカス、編集競合は本実装時の検証事項である。

| 要件 | 現行モックの操作・状態 | 制約・残件 |
|---|---|---|
| FR-401～403/407 | 上部ボタンから約420×560のブラウザ別窓を開く。ポップアップ不可ならページ内小窓を表示。閉じる／最小化相当のボタンがある。 | OS全域ショートカット、最前面、ネイティブ最小化、常駐はない。閉じると最小化は実質同じ非表示処理。 |
| FR-404/405 | 資料検索、概要・詳細・編集、簡易メモ、ルビ、共通取り込み、保管庫を切り替える。 | 全文表示の初期範囲、編集開始、メモ保存先は未決。メモは永続化しない。Quick Recall内の保管庫にはゴミ箱へ移す操作がない。 |
| FR-406 | 別窓は独立したページ状態で開始する。 | メイン窓との本文・メモ同期、二重編集時の競合・保存順序は未実装／未決。 |

### 3.6 初回利用・設定・テーマ（FR-501～FR-504）

- **初回利用**：製品要件は新規作品作成を優先し、短い説明または内蔵動画を案内する方向。現行モックでは作品画面から3操作の「初めての使い方」を開く。案内形式は未決で、作品0件の初期状態も未実装。
- **オフラインとAI**：通常の資料管理、編集、検索、参照をオフラインで使う方針。AIの用途、ローカルLLM／APIの選択、自動実行範囲は未決。現行モックは外部APIに接続せず、AI入口を表示しない。
- **バックアップ**：製品の初期方針は手動エクスポートで、自動バックアップは将来候補。現行モックは出力を行わない。
- **テーマ**：上部セレクタで3テーマを切替え、選択だけをブラウザに保持する。機能・データ・画面構造は共通。
