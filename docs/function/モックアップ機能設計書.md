# Novel Lore Manager モックアップ機能設計書

- 作成日：2026-11-15
- 対象：`mockups/novel-lore-manager/index.html` を起点とする現行ブラウザモック
- 文書の目的：現在操作できる機能、モック固有の制約、未実装、未確定、使用ファイルを分けて示す

## 1. 判定基準と参照資料

| 表記 | この文書での意味 |
|---|---|
| 実装 | 現行コードにブラウザ内の操作経路がある |
| 模擬 | 操作はできるが、結果はページ内データだけに反映される |
| 一部実装 | 画面・操作の一部はあるが、要求された状態や復帰経路の一部がない |
| 未実装 | 現行コードに操作・状態がない。製品機能がモック対象外の場合はその旨を明記する |
| 未確定 | 要件・画像の解釈や本実装方式に判断が残る。モックの挙動を承認済み製品仕様と見なさない |
| 未検証 | コード上の経路は確認したが、実ブラウザの表示・操作で確認していない |

主な根拠は [やって欲しいこと2.md](やって欲しいこと2.md) の末尾「修正して欲しいところ」、[未実装・未確定まとめ.md](未実装・未確定まとめ.md)、および現行のHTML・CSS・JavaScriptである。製品要求の位置付けは [requirements.md](requirements.md)、[data-management-design.md](data-management-design.md)、[user-flows.md](user-flows.md)、[screen-specifications.md](screen-specifications.md) に従う。前者の途中にある過去の調査表や [機能設計書_現行モック_2026-11-11.md](機能設計書_現行モック_2026-11-11.md) と現行コードが食い違う箇所では、現行コードを機能判定の根拠とした。特に作品別資料の退避・復元、直近3作品、作品名検索は現在のモックに存在する。

本書はモックの現状を記述する。要件文書の `CONFIRMED` は目標の合意、`PROVISIONAL` は仮仕様、`OPEN` は要検討、`FUTURE` は将来拡張を示し、現行コードの「実装」とは別の軸である。

## 2. 実行範囲とデータ境界

- Windowsデスクトップ向け設定資料アプリを、HTML5・CSS3・Vanilla JavaScript（ES Modules）で表したローカル試作。小説本文の執筆エディタではない。
- 通常起動は `index.html`。Node.js の `preview.mjs` で `127.0.0.1:4173` に静的配信し、ES Modulesを読み込む。`file://` 起動は想定しない。
- 初期作品「灰冠の王国」に架空の設定資料6件（人物3、世界観2、組織1）を用意する。新規作品、資料、編集内容、履歴、ルビ辞書、簡易メモ、保管状態、取り込み結果はブラウザページのメモリ内にある。再読み込みすると初期状態に戻る。
- 作品の `documents`、開いているタブ、選択資料などを作品切替時に退避・復元する。ただし作品をまたぐ一連の操作はブラウザでの通し検証が未了。Quick Recallの別窓は独立したページ状態で始まり、メイン窓の変更を同期しない。
- テーマ選択だけ `localStorage` の `nlm-theme` に保持する。資料の「保存」、インポート、アーカイブ、ゴミ箱、復元は実ファイルやDBを変更しない。選択ファイルは名前と相対パスのみ参照し、本文は読み取らない。
- 現行の対象JSに外部API呼び出しはない。起動画面の季節・時間帯は端末の日時から決める。ローカル静的配信と、画面から開き得る通常のHTTP(S)リンクは外部API連携とは区別する。

## 3. 画面構成・遷移

| 画面 | 到達経路と主な遷移 | 現状 |
|---|---|---|
| スタート | 通常起動 →「作品を選ぶ」→ 作品作成・選択 | 実装。端末の月・時刻に応じたピクセル調の木と背景を表示 |
| 作品作成・選択（SCR-01） | スタート、ワークスペースの戻るボタン → 既存作品または新規作品 | 模擬。最近開いた作品、全作品、新規作成フォームを表示 |
| 最初の設定資料 | 新規作品の本を開く → 資料作成 → 作品内検索 | 模擬。作品内の最初の資料を追加 |
| 資料一覧・編集（SCR-02/03） | 作品を開く、左メニュー、検索結果から開く | 実装。保存は模擬 |
| 作品内検索（SCR-04） | 左メニュー、通常画面の `Ctrl+F` | 実装。結果プレビューから資料を開く |
| 取り込み（SCR-05） | 左メニュー、Quick Recall内 | 模擬。5段階のウィザード |
| Quick Recall（SCR-06） | 上部ボタン、`index.html?recall=1` | ブラウザ小窓または同一ページの小窓として模擬 |
| ルビ辞書・一覧 | 左メニュー、Quick Recall内 | 模擬。登録、一覧、検索、削除など |
| 保管庫（SCR-08） | 左メニュー、Quick Recall内 | 模擬。通常・アーカイブ・ゴミ箱を区別 |
| 初回ガイド（SCR-07の一部） | 作品画面の「初めての使い方」 | 一部実装。3操作の説明ダイアログ |

画面は共通DOMと共通JSを使用し、Forest Workbench／Storybook Atelier／Quiet Lore Studioの3テーマではCSSだけを切り替える。作品画面へ戻るときは未保存資料全件について保存・破棄・キャンセルを選ぶ。通常の左メニュー切替には同じ確認を通さない。

## 4. 現在の機能設計

### 4.1 スタート・作品

| ID | 操作と状態 | モック上の制約 |
|---|---|---|
| M-01 | 起動時にアプリ名と季節の木を表示。春・夏・秋・冬、朝・昼・夕・夜を端末日時から起動時に一度選ぶ | 外部の時刻・天候サービスは使わない。参照画像との視覚的一致は未検証 |
| M-02 | 最近開いた作品を `lastOpened` 順に最大3冊表示。全作品を本型で表示し、作品名検索、最近開いた順／作品名順に切替 | 履歴はメモリ内。最終更新日時・著者・進行状態・個別表紙画像は持たない |
| M-03 | 作品名・ジャンル・仮表紙を選んで新規作品を作成。作品名の空欄・重複を検査。新規作品は空の資料配列で始まる | 作成と作品別データは再読み込みで消える。全作品が0件の起動状態はない |
| M-04 | 新規作品の本を開き、資料名・カテゴリ・Markdown本文を入力して最初の設定資料を作る | 資料名の空欄・同名を検査。作成後は検索画面へ進む |

### 4.2 資料一覧・Markdown編集

| ID | 操作と状態 | モック上の制約 |
|---|---|---|
| M-05 | 通常状態の資料を固定フォルダ領域、カテゴリ、タブ、関連資料から開く。フォルダは展開できる | 登場人物・世界観・組織の領域は固定。任意階層・カテゴリ編集・タグ編集はない |
| M-06 | 資料IDを使ってタブを開閉し、編集／プレビュー／左右分割を切替。右側に別の開いた資料を参照表示できる | パネルの自由配置はない。右側は参照表示 |
| M-07 | 画面の区切りをポインターまたは左右キーで調整。Markdownガイドを開ける | 調整幅は画面内だけ。配置の永続化はない |
| M-08 | 入力内容と保存済み本文の差で未保存表示。保存ボタン／`Ctrl+S` はメモリ内の保存済み本文を更新 | ディスク保存、自動保存、保存失敗はない |
| M-09 | 入力履歴を資料ごとに最大100件保持。Undoボタン／編集欄の `Ctrl+Z` で戻す | Redo・永続履歴・クラッシュ復旧はない |
| M-10 | 未保存タブを閉じる際に保存・破棄・キャンセルを提示。作品画面へ戻る際にも未保存資料を確認 | ページ離脱警告の表示はブラウザ依存。全画面遷移に統一された確認ではない |
| M-11 | 限定Markdownと `[[資料名]]`、`｜語《読み》` をプレビュー。入力された生HTMLは文字として表示 | 画像、任意HTML、完全なMarkdown仕様には対応しない。資料リンクは表示名完全一致で解決 |

プレビュー対象は見出し1～6、引用、箇条書き、番号付きリスト、水平線、太字、斜体、インラインコード、HTTP(S)リンク、資料リンク、仮のルビ記法である。

### 4.3 検索・ルビ

| ID | 操作と状態 | モック上の制約 |
|---|---|---|
| M-12 | 通常資料のタイトル・明示した別名・タグ・本文を部分一致で検索。NFKC正規化と日本語ロケールの小文字化を適用 | 漢字の読み推定、一般的な表記ゆれ解決、作品横断検索はない |
| M-13 | 全資料／現在資料、フォルダ→カテゴリ→タグの順の絞り込み、名前順／仮の関連度順を選択 | 「関連度順」は実スコアではなく初期配列順 |
| M-14 | 件数・抜粋・簡易強調・結果プレビュー・資料を開く操作、0件表示と条件解除 | 強調は単純な文字位置処理。検索失敗を模擬する経路はない |
| M-15 | ルビ辞書に単語・読み・投稿先を登録、一覧・削除。編集欄で候補をTabまたはクリックで挿入 | 辞書はメモリ内。投稿サイト別表記は仮の表示例で、正規の変換・出力ではない |

### 4.4 取り込み・Quick Recall・保管庫

| ID | 操作と状態 | モック上の制約 |
|---|---|---|
| M-16 | `.md`／`.txt` のファイル・フォルダ選択、ドラッグ投入、サンプル2件を受け付ける。対象→管理方式→整理方式→確認→結果の5段階 | 拡張子と同じパスの重複を判定。ファイル本文・文字コード・権限は調べない |
| M-17 | COPY／DIRECTの想定、元階層保持／カテゴリ別整理を一括選択。同名候補を確認して仮取り込み | 同名タイトルは自動スキップ。衝突ごとの選択はない。資料名と固定のダミー本文を追加し、失敗0件を表示 |
| M-18 | Quick Recallで資料検索、概要・詳細・編集、簡易メモ、ルビ、共通取り込みウィザード、保管庫を切替 | 別窓は独立メモリで同期しない。メモも永続化しない。Quick Recall内の保管庫はゴミ箱へ移す操作がない |
| M-19 | ブラウザ別窓（約420×560）を開き、ポップアップ不可ならページ内小窓を表示。閉じる／最小化相当のボタンを用意 | OS最前面固定・全域ショートカット・ネイティブ最小化はない。2ボタンは実質同じ非表示処理 |
| M-20 | 保管庫に通常／アーカイブ／ゴミ箱の状態タブと件数・空状態を表示。題名は左寄せ。名前・タグ・本文の検索と登録済みタグの選択絞り込みを提供 | タグの自由入力検索はない。状態変更はメモリ内のみ |
| M-21 | アーカイブ・ゴミ箱へ移す前に確認。未保存なら保存／破棄／キャンセル。移動先から通常へ復元 | 完全削除、実ファイル移動・削除、復元時の名前・パス衝突確認はない |
| M-22 | 上部のセレクタで3テーマを切り替え、選択をブラウザに保持 | 機能・データ・画面構造は共通。資料状態の永続化とは別 |

## 9. 確認方法と限界

`mockups/novel-lore-manager/` で `node preview.mjs` を起動し、`http://127.0.0.1:4173/` を開く。Quick Recallの単独画面は `index.html?recall=1`。旧 `quick-recall.html` は現行の確認先ではない。

本書は2026-11-15時点のソース確認と既存の調査記録を基にした。`tests/smoke.mjs` は検索・Markdown安全性・テーマ資産などを扱うが、全画面遷移、別窓同期、3解像度・3テーマの見た目、スクリーンリーダーでの品質を保証しない。外部APIへの接続、パッケージ追加、実ファイルの取り込み・編集・削除は行っていない。
