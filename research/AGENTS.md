# 調査共通ルール

1. 調査開始時に `research/common/research-policy.md` と `research/common/evidence-policy.md` を読む。
2. 調査は `research/B/config.yaml` の工程順に進める。YAMLは独自の**作業定義データ**であって自動実行エンジンではない。
3. 情報の状態は `確認済みの事実 / 個人の経験・意見 / 分析・仮説 / 未確認` の4区分。
4. 重要な主張には `CLAIM-ID`、根拠には `EVIDENCE-ID`、未解決の反論には `DISSENT-ID` を付ける。
5. 内部管理情報は構造化して記録し、**研究報告、専門分析、最終報告は平易な日本語**で書く。
6. 公開サイトの規約を守り、ログイン突破、無許可収集、大量スクレイピングをしない。
7. 作業対象以外のシナリオA/C、`src/`、`docs/product/feature-inventory.md` はB実行で読まず、変更しない。
8. 重大な出典不足・技術的制約・法務懸念は報告に残し、隠さない。
9. 研究レポートは完成済みと装わず、実際の調査ができなかった場合 `未調査` のまま提出する。
