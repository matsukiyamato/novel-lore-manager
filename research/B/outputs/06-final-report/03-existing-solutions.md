# 今の方法でできる？
今ある道具と、簡単な記録ルールで解決する場合がある。
新しいアプリの方が速い・簡単とは、まだ比べていない。
乗り換えない方法も有力な選択肢として残す。

## 道具を増やさず試す
作品ごとに保存先を決める、正式な設定だけ短く残す、前回の作業と次の確認先をメモする、変更前のコピーとバックアップを残す。この運用案を、試作と比べる基準にする。

設定集にOneNote、年表にExcelを使う本人例や、短いメモで決定を分ける本人例がある。複数の道具を使うことが、いつも悪いとは言えない（CL-B-0010/0011）。

## 6つの製品を確認した
| 製品 | 確認したこと | 注意 |
|---|---|---|
| Nola | 公式紹介文は人物・プロットの管理を説明 | 現行の詳しい仕様・料金・入出力・操作は未確認 |
| Obsidian | ローカルのMarkdown、通常検索、復旧用コピー | 正式設定の印や作品分けは利用者の工夫が必要。復旧用コピーは完全なバックアップではない |
| Notion | 通常検索、制限付きオフライン、Markdown等の書き出し | オフラインと完全なローカル専用は違う。移行で構造やリンクが保たれるかは未実測 |
| OneNote | Windowsデスクトップ版の横断検索、事前バックアップからの復元 | 版・契約による条件、md/txtとの行き来は別確認 |
| 秀丸 | 複数ファイルから文字を探し、該当行へ移動 | 正式かどうかは、保存や記録のルールも必要 |
| VS Code | フォルダ検索と標準のローカル履歴・復元 | 保存・保持の設定に制限がある。検索に追加拡張が必須とはしない |

根拠はCL-B-0015〜0026、[製品別の出典と未確認事項](../01-research/competitors.md)に記録した。追加拡張Longformの本人例を、Obsidianの標準機能として数えていない。掲載がない機能を「実現不能」とは判断していない。

## 比べるときの注意
初回整理、移行、毎日の登録、探す、直す、戻す、再開するまでを含める。検索を開くキーが短いだけでは便利さの比較にならない。使い慣れた道具と初めての試作で、練習量が違うことも考える。

開発者が判断すること: 比較の基準にする運用。保留: 最速の製品、最安の製品、乗換率、競争優位。
