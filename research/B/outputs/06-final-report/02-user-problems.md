# 何に困る？
資料がどこにあるか、どれが正式か、前回何を決めたかで、困り方が違う。
誰がどのくらい困るかは、まだ十分には分からない。
次の6つを分けて確かめる。

| 困りごと | 起きる場面 | うまくいった状態 |
|---|---|---|
| 置き場所が分からない（PR-B-01） | いくつかのアプリ・端末から設定を探す | 作品を間違えず、元の資料に戻れる |
| 正式な内容を選べない（PR-B-02） | 案を出した後や設定を変えた後 | 正式・候補・廃止の違いと理由が分かる |
| 再開時に思い出せない（PR-B-03） | 忙しい時期や休みの後 | 前回の決定と次にすることが分かる |
| 関連情報が離れている（PR-B-04） | 人物や場所の別の資料を確認する | 必要な関連情報と出所を確認できる |
| 変更を戻せない（PR-B-05） | 誤って消したり書き換えたりする | 元の内容と資料一式を復元できる |
| 整理自体が負担（PR-B-06） | 初回の移行や毎日の記録 | 登録・修正の負担が、得られる利益を超えない |

## 例で考える
「この人物の目の色」を探すと、古い案と新しい案が両方見つかるとする。検索が速くても、どちらを正式として使うか分からなければ困りごとは残る。この例は説明用で、取材で見た実例ではない。正式情報を選ぶ問題を分けた理由は、開発者の観察と、決定・廃止が混ざる外部作者の報告にある（CL-B-0006/0010/0036）。

## 全員の問題ではない
最初の5つは本人報告や既存の対処例をもとに整理した。6つ目は、管理のための入力が増えるという分析上の懸念で、負担を測った結果ではない（CL-B-0037）。既存ツールで困らない作者、資料の少ない作者には別の結果がありうる。

休筆後の困難は開発者とAI併用の外部例に偏る。非AI作者にも同じように起きる割合は不明。人物が知る情報と作者が知る情報の区別を、全員に記録させる根拠も不足している。

## 開発者が判断すること
最初に観察する困りごとを選ぶ。保留するのは、多い順の順位や「全員に必要」という判断。[課題と根拠の詳しい表](../03-analysis/user-problems.md)、[出典](../02-evidence/evidence-register.md)で確認できる。
