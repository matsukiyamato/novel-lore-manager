# Novel Lore Manager — 共通情報設計・操作設計

状態：設計提案（2026-11-02）。3テーマ共通。画面・操作の比較用であり、製品仕様の承認や実装完了を意味しない。

## 根拠と境界

- 上位資料：`docs/requirements.md` v1.1-draft、`docs/data-management-design.md` v0.1、`docs/user-flows.md` v0.1、`docs/screen-specifications.md` v0.1。実在パスを確認済み。
- **確定方針**：Windows向け設定資料管理、作品単位、フォルダとカテゴリ、主カテゴリ1つと複数タグ、複数タブ・左右分割、Markdown編集／プレビュー、手動保存、作品内検索、独立したQuick Recall、ゴミ箱とアーカイブの区別。
- **モック限定**：保存・削除・取り込みは架空データの状態変化。ブラウザでOS全域のショートカット、常時最前面、他アプリへのフォーカス復帰は保証しない。
- **暫定設計**：下記の領域順、パネルの初期寸法、ツリーのキー操作、Quick Recallの縦積み、検索結果の選択と開くの分離。同一資料の単一論理IDも暫定。
- **未決**：パネル自由配置と記憶、同名判定、外部更新と二重編集、Quick Recallの対象作品・閉じる動作・ホットキー、ゴミ箱表示条件、メモの永続化。関連するIDは画面仕様 §17 の DM-Q01〜08／UX-Q01〜06。
- **将来拡張**：作品横断検索、AI・RAG、同期、自動バックアップ。初期UIに入口を置かない。

## 情報アーキテクチャと移動

```text
作品選択 SCR-01
└─ 現在の作品 SCR-02
   ├─ 資料を探す：フォルダ / カテゴリ / タグ → 同一資料ID
   ├─ 開いている資料：タブ → 編集・プレビュー・左右分割 SCR-03
   ├─ 作品内検索 SCR-04 → 結果選択 → プレビュー → 資料タブ
   ├─ 取り込み SCR-05 → 確認・結果 → SCR-02
   ├─ 通常 / アーカイブ / ゴミ箱 SCR-08 → 復元・解除
   └─ 設定・ガイド SCR-07
独立小窓 SCR-06 Quick Recall → 対象作品内を検索 → 概要 → 詳細 / 編集 / 別メモ
```

作品を最上位の境界とし、作品横断の一覧・検索は作らない。フォルダは保存位置、カテゴリとタグは分類・絞り込みであり、カテゴリ変更をファイル移動に見せない。ツリー、検索結果、リンク、タブ、Quick Recallは同じ資料を別入口から参照する。表示名を識別子の代わりにしない（論理ID案は未承認）。

左端の機能ナビは「資料」「検索」「取り込み」「ゴミ箱・アーカイブ」「設定」の文字ラベルを付け、現在位置を面・線・文字で示す。上端に作品名、作品選択へ戻る、Quick Recall、テーマ切替を置く。作品切替はSCR-01を経由し、未保存時はMOD-01を通る。テーマだけを替えても現在作品、タブ、入力、スクロール、フォーカスを保つ設計とする。

## SCR-02 ワークスペース

| 領域 | 順序と役割 | 暫定操作 |
|---|---|---|
| 上端 | 作品名、作品選択へ戻る、Quick Recall、テーマ | 作品切替は未保存を確認 |
| 機能ナビ | 資料・検索・取り込み・ゴミ箱／アーカイブ・設定 | 現在ビューを明示 |
| 左パネル | フォルダツリー、カテゴリ、タグ、資料名 | 展開、選択、幅調整、折りたたみ |
| 中央 | 資料タブ、資料見出し、編集／プレビュー／左右分割、保存、Undo | タブ選択・閉鎖、別タブを右に表示 |
| 右パネル | 関連資料・リンク先 | 閉じる／再表示。左右分割時の競合を避け、関連情報は折りたたむ案 |
| 下端 | 保存状態、COPY／DIRECT、作品または検索範囲 | 状態を文字で常時確認 |

フォルダツリーの選択は単一資料をタブで開く。タブを替えるだけでは未保存内容を破棄しない。タブの「選択」と「閉じる」は別の到達可能な操作にする。分割時には左右それぞれの資料名と所属タブを表示し、どちらを編集・保存するかを明示する。同じ資料を両側に開く場合は単一ドラフトとして扱う案だが、実装方式はDM-Q01／06未決。関連パネルと第2資料ペインを同じ「右パネル」と呼ばない。

パネルの境界には目で分かるつまみを置き、ポインタ操作に加え「幅を広げる／狭める／初期幅に戻す」をキーボードまたはメニューで提供する案。左パネル初期264px・最小220px、関連パネル初期248px・最小220pxは既存 `shared-layout.md` の暫定値。中央の最小実用幅を先に確保し、収まらない場合は関連パネルを閉じる操作を案内する。自由ドッキングや自動記憶は確約しない。

## SCR-04 検索と結果移動

検索を開くと検索欄に到達できる。初期範囲は「作品内全資料」。「現在開いている資料」への切替を明示し、現在資料がない時は理由を表示する。フォルダ・カテゴリ・タグを絞り込みとして並べ、適用中の条件をラベルで読み取れるようにする。結果は初期「関連度順」で、並び替え候補は暫定とする。

結果行は資料名、所在、ヒット抜粋、該当語、状態を含む。矢印キーで結果内の選択を移し、プレビューを更新する。`Enter` または「資料を開く」で中央のタブを開く案とし、選択だけで編集画面へ飛ばさない。プレビューの一致位置と結果の抜粋は対応させる。検索に戻ったときは入力、フィルタ、結果選択、一覧スクロールを復元する。ヒット強調は色だけでなく太字・下線等を併用する。読み・別名は登録済みモック情報への照合であり、任意の漢字の読みを推定するものではない。

## SCR-06 Quick Recall

独立小窓の初期寸法約420×560pxは仮値。作品名と検索欄を上部に固定し、その下に結果一覧、選択資料の概要を縦に置く。狭い小窓で横2列にすると日本語の抜粋と概要が短くなるため、既存の横並び案から変更する提案である。詳細／全文、資料編集、簡易メモは明示操作で一つずつ展開する。メモは資料本文と別状態として表示し、未保存を独立表示する案（DM-Q06未決）。

小窓内は対象作品を明示し、作品未選択なら検索結果を装わず作品選択の案内を出す。結果選択→概要→詳細→戻るで一覧の選択とスクロールを保持する。最小化相当の操作と閉じる操作は別ラベルにし、ブラウザモックでは「非表示相当」と明記する。実際のWindows前面固定や執筆アプリへのフォーカス復帰を画面文言で保証しない。編集競合は保存を止め、双方の内容を保持してMOD-03へ進む。

## 状態と回復導線

| 状態 | 必ず見える情報 | 次の操作 |
|---|---|---|
| 作品／資料／タブが空 | 何が空かを明示。資料0件なら「新しい資料」「取り込む」 | 作成、取り込み、作品選択 |
| 資料選択中 | 資料名、所在、カテゴリ、現在タブ、編集対象 | 編集、プレビュー、分割 |
| 未保存 | タブと状態欄に「未保存」。色のみ不可 | 保存、Undo、離脱時MOD-01 |
| 保存失敗 | 理由、対象資料、ドラフトが保持されていること | 再試行、編集続行 |
| 検索0件 | 「0件」、検索範囲と適用フィルタ | 条件を変える、フィルタ解除 |
| 衝突・外部変更 | 何と何が競合するか、保存が停止したこと | 比較、名前変更／スキップ／キャンセル。自動上書きなし |
| ゴミ箱 | 「削除済み」と元の場所、復元可否。薄い文字だけにしない | 復元、文脈に応じた確認 |
| アーカイブ | 「アーカイブ済み」と通常資料との差 | 解除、ゴミ箱へ移動 |
| 復元衝突 | 復元先と既存名、元資料が保持されていること | 名前変更、キャンセル |
| Quick Recallメモ未保存 | 資料本文とは別の「メモ未保存」 | メモ保存、離脱確認 |

MOD-01〜04は見出し、対象、影響、選択肢を本文で示す。初期フォーカスは「キャンセル」等の安全な操作。`Esc` はキャンセルし、元の起点へフォーカスを戻す。保存失敗や競合でドラフトを消さない。完全削除とDIRECT資料への実ファイル処理は今回のモックでは行わない。

## キーボード、読み上げ、文字長

- 画面に入ったら主領域へ移る手段を設ける。通常のTab順は上端→機能ナビ→左探索→タブ・操作→編集／検索本文→関連情報→状態欄のうち操作可能部分。非表示領域はTab順から除く。タブ・ツリー・結果一覧の内側は矢印キーで移動し、Tabの停止数を増やし過ぎない案。
- ツリーは上下矢印で項目、左右矢印で開閉、`Enter` で資料を開く。タブは左右矢印で選択、`Delete` など破壊的キーには割り当てず閉じるボタンを用意する。キー割当はモックの仮案で、Windows・支援技術との衝突を実装時に確認する。
- `Ctrl+S` と `Ctrl+Z` は確定方針。`Ctrl+F`／`Ctrl+Shift+F`、`Ctrl+Tab` は画面仕様上の仮割当。ブラウザ標準操作との衝突を確認する。Quick RecallのOS全域ホットキーは未割当。
- フォーカス輪郭は常時視認可能な2px以上を案とし、選択状態とは別に表現する。固定ヘッダー、ダイアログ、スクロール端でフォーカス対象を隠さない。モーダルを閉じたら起点へ戻す。検索結果・保存状態の更新でむやみにフォーカスを動かさず、必要な文脈だけ通知する。
- 入力には表示ラベル、エラーには原因と修正方法を付ける。複数エラー時は要約から各欄へ移れるようにする。アイコンだけの操作にはアクセス可能な名前と状態を付け、飾りアイコンは読み上げから外す。
- 日本語本文は16px以上、行高1.5〜1.75、読み物の1行は概ね60〜75字を目安。長い資料名・タグ・ルビ・URLは通常は折り返し、タブやツリーで省略するなら全文をポインタとキーボード双方から確認できるようにする。URL等の長い連続文字だけ任意位置折り返しを許す。日本語の通常文を1文字ずつ強制分割しない。
- 文字での状態表示を維持したまま、通常文字4.5:1、意味を持つアイコン・境界・フォーカス3:1を各テーマの実際の面色で検証する。動きは控えめにし、`prefers-reduced-motion` を尊重する。
