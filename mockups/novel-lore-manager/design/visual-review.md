# 3テーマ視覚レビュー — 現行モック

2026-11-02。対象は `index.html` のワークスペース（1440×900想定）と `quick-recall.html` の単独小窓（420×560想定）。Forest Workbench / Storybook Atelier / Quiet Lore Studio を同じ内容・状態で比較するため、初期資料は「灰冠の王国／エレナ・ヴァルツ」、Markdownは初期値、Quick Recallは「エレナ」検索・先頭結果選択・詳細とメモを閉じた状態に固定した。未保存状態はコード上の状態遷移を別途点検した。

## 確認方法と限界

- `docs/requirements.md`、`docs/data-management-design.md`、`docs/user-flows.md`、`docs/screen-specifications.md` と現行HTML/CSS/JSを実読。`node preview.mjs` で両URLのHTTP 200、`node --check` で `js/theme-manager.js`、`scripts/app.js`、`scripts/data.js` の構文を確認した。
- ブラウザ操作ホストは `The browser access host is unavailable` を返した。したがって**指定サイズでの実描画、スクリーンショット、文字の実測、Tab移動・フォーカスの見え方、スクロール、テーマ切替後の状態保持は未検証**。以下の幅はCSS宣言からの計算であり、描画寸法の実測ではない。
- `ui-ux-pro-max/SKILL.md` のQuick Reference §1（焦点・名前・色以外の状態）、§5–6（行長・文字・階層）、§8–9（エラー・検索導線）を照合。今回は既存UIの対象を絞ったレビューで、新しい視覚方向を生成しないため `--design-system` は実行していない。Python 3も `Get-Command python,python3,py` で見つからず、`search.py` の一致結果は**未取得**。過去の `ux-research-log.md` にある実行待ち項目を検索結果として扱わない。スキルの `references/pro-rules.md` は実在せず、最終レビューにはSKILL本文を用いた。
- `frontend-design/SKILL.md` の「素材の比喩は一箇所に絞る」「日本語本文を装飾しない」「形と余白で情報を示す」を批評の基準とした。実ユーザーへの観察・疲労測定・好みの調査は行っていない。

## 比較の前提にある実装差分

`index.html` は `css/` と `js/theme-manager.js` を読み込む6資料のワークスペースで、初期状態から分割編集を表示する。一方、`quick-recall.html` は `styles/` と `scripts/app.js`・`scripts/data.js` を読む12資料の小窓である。画面ごとのDOMが異なること自体は小窓の役割に合うが、資料データ、状態管理、`localStorage` キー（`nlm-theme` と `nlm-mock-theme`）の違いは、両画面を同一シナリオとして比較する妥当性に影響する。READMEは作品内検索等を実装済みとしているが、現在の `index.html` はその機能を持つ `scripts/app.js` を読み込まない。Quick Recallのエレナ概要は `app.js` が本文先頭150字から再生成するため、HTMLに書かれた概要文とも一致しない。

## 仮の重みに沿った比較

重みは優先順を示す**仮値**であり、点数・順位・客観的ユーザーテスト結果には変換しない。3テーマは各画面内で同一DOMとほぼ同一寸法を使うため、操作上の強みと欠点の大半は共通である。

|---|---:|---|---|---|

## テーマ別の視覚批評

- **Forest Workbench**：深緑の作業面と明るい文字、選択線の組合せは設定資料の「作業机」に合う。木目・発光を足していない節制は良い。現行の2系統のForest CSSで境界色がずれ、同じ世界観に見えるかは未検証。暗色の疲労感はコードから判断できない。
- **Storybook Atelier**：紙面の色差と見出し限定の明朝は、古書の雰囲気を本文の可読性と両立させる意図が明確。染みやページ演出がなく、資料作業に集中できる設計。和文明朝の実際の太さ・行高、選択面と枠の見え方は未検証。
- **Quiet Lore Studio**：セージ色を選択・位置の手掛かりに使い、本文面は無地。青い焦点色の分離は操作状態を理解しやすくする狙いがある。明るい面だけでは汎用の業務ツールにも見えるため、選択帯が小窓まで一貫して認識できるか実描画で確認する。

## 次の検証順と変更範囲

1. 共通データ・テーマ状態・入口の食い違いを修正し、両画面に同じ資料・検索語・結果集合を出す。これは比較条件の修正であり、本番機能追加ではない。
2. 1440×900／420×560で3テーマ×2画面のスクリーンショットを取得し、Markdownの実行長、選択線、境界、Quick Recallの省略とスクロールを比較する。
3. キーボードのみで検索→結果→資料、編集→未保存→保存、Quick Recall検索→概要→詳細→メモ→閉じるを同順に試す。フォーカス可視性・遮蔽・戻り先を記録する。
4. 必要な修正は原則として共通CSSの文字・枠・余白とテーマCSSの色・質感に限定する。検索など必須ビューの接続は別工程で扱い、仕様の確定／暫定／未決／将来拡張を変えない。

このレビュー工程で**コードは変更していない**。未実装・未検証を点数で埋めず、次の同条件テストで判断する。
