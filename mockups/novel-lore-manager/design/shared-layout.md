## 設計原則

1. 最上位は「作品」、次に「探す場所」、次に「資料」、最後に「資料の操作」。本文執筆用の機能や統計ダッシュボードは置かない。
2. フォルダ・カテゴリ・検索結果・タブ・Quick Recallは、同じモック資料を別の入口から参照する。カテゴリ変更をファイル移動として見せない。
3. 主要操作は画面上に名前を表示する。アイコンだけのナビゲーションを避ける。各画面の強いアクションは一つを基本とする。
4. 情報密度は全テーマで同じ。Forestだけタブや行を詰めたり、Storybookだけ本文幅を広げたりしない。
5. 状態は文字＋形で示す。「未保存」「保存済み」「保存に失敗」「アーカイブ」「ゴミ箱」「元ファイルを直接編集」を色だけに頼らず区別する。

## 共通の画面骨格（暫定）

```text
┌──────────────────────── 作品名・戻る・検索・Quick Recall・テーマ ───────────────────────┐
│ 機能ナビ │ 資料一覧／カテゴリ │ タブ群・資料名・保存／モード切替        │ 関連資料       │
│          │                    │ ┌──── 編集／プレビュー／分割 ──────┐ │                │
│          │                    │ │ 設定資料の本文／検索結果／ゴミ箱 │ │                │
│          │                    │ └─────────────────────────────────┘ │                │
├──────────────────────────────── 保存状態・管理方式・現在作品 ───────────────────────────┤
└───────────────────────────────────────────────────────────────────────────────────────────┘
```

| 領域 | 共通内容・振る舞い | 暫定基準 |
|---|---|---|
| 上端 | 作品名、作品選択へ戻る、検索、取り込み、Quick Recall、テーマ切替 | 高さ56px、順序固定 |
| 機能ナビ | 資料、検索、取り込み、ゴミ箱／アーカイブ、設定 | 幅72px。アイコン＋日本語ラベル |
| 左パネル | フォルダ、カテゴリ、タグ、資料ツリー。選択・展開・空状態 | 標準幅264px、最小220px、幅調整は暫定 |
| 中央 | 資料タブ、資料名、編集／プレビュー／左右分割、保存、Undo、内容 | 残余幅。左右分割時は2ペインの見出しを維持 |
| 右パネル | 関連資料とリンク先、閉じる操作 | 標準幅248px、最小220px。必要時に閉じられる |
| 下端 | 保存状態、COPY／DIRECT、現在作品。検索時は検索範囲 | 高さ32px。状態文字を常時読める |

1366×768では中央の読み幅を優先し、右パネルを閉じられる。1440×900と1920×1080でも同じ初期構造を用い、広い中央領域の本文行幅だけを最大約72字に抑える。拡大表示125%／150%では右パネル、次に左パネルをユーザー操作で閉じられるようにする。隠した領域は同じナビから再表示できる。パネルの自動並べ替えや自由ドッキングは未決であり、この設計で確約しない。

## 画面別の共通配置と操作

| 画面 | 情報の順序と主操作 | 空・失敗時 |
|---|---|---|
| 作品選択 SCR-01 | 製品名→新規作品作成→既存作品一覧→初回ガイド。作品切替はここへ戻る | 0件なら作成を案内。名前エラーは入力の近くに示し、入力を保持 |
| ワークスペース SCR-02 | 作品→探索入口→資料→タブ→本文→関連資料。フォルダとカテゴリは同一資料を開く | 資料0件なら「新規資料を作成」「取り込む」 |
| Markdown SCR-03 | 資料名・未保存状態→編集／プレビュー／左右分割→本文→保存・Undo | 保存失敗は本文を保持し、理由と再試行を表示。離脱は保存／破棄／キャンセル |
| 検索 SCR-04 | 入力→範囲（初期は作品全体）→フォルダ・カテゴリ・タグ→関連度順→結果→本文プレビュー | 0件は条件変更・解除。エラーは再試行。作品横断入口なし |
| 取り込み SCR-05 | 対象→管理方式→整理方式→確認→結果。各段階で戻れる | 0件・衝突・失敗の対象と理由を示し、上書きしない。実ファイルは扱わない |
| Quick Recall SCR-06 | 作品名→検索→結果→概要→詳細／編集／簡易メモを必要時展開→最小化 | 作品未選択・0件・メモ未保存・競合を明示。OS最前面は模擬表現のみ |
| ゴミ箱／アーカイブ SCR-08 | 通常／アーカイブ／ゴミ箱→一覧→復元・解除。完全削除は確認 | 状態ごとの0件を表示。DIRECTの実ファイル削除は行わない |
| 設定 SCR-07 | テーマ切替を同位置に置く。文字サイズ・密度は暫定項目 | 切替後も資料・タブ・スクロール・入力値を維持する設計 |

## 共通コンポーネントと状態

- `Project switcher`：作品名と「作品選択へ戻る」。未保存資料があれば確認する暫定動作。
- `Explorer tree`：展開、選択、現在位置、ゴミ箱内の印。ツリーの行は色に加えて「削除済み」等の文言を付ける。
- `Document tabs`：選択、閉じる、未保存印、左右ペインの所属。長い資料名は折り返しまたは省略時に全文を取得できる。
- `Mode switch`：「編集」「プレビュー」「左右分割」。選択状態は下線／面と `aria-pressed` 相当で示す。
- `Status`：「未保存」「保存済み」「保存に失敗」、COPY／DIRECTを同じ位置に表示。保存失敗の通知でフォーカスを奪わない。
- `Search result`：資料名、フォルダ、抜粋、ヒット強調。強調は背景色だけでなく太さまたは下線も使う。
- `Wizard`：現在ステップ名、戻る／次へ、管理方式の影響説明、確認要約。失敗項目は対象に隣接させる。
- `Dialog`：見出し、影響、実行／キャンセル。初期フォーカスは安全な操作、Escは確認なしで破壊的操作を実行しない。
- `Quick Recall`：主画面と同じ資料名・状態語彙。省スペースでも検索入力のラベルと最小化操作を残す。

## アクセシビリティと検証基準

- 日本語本文は原則16px以上・行高1.55以上、長文の1行は約60–75字。小型ラベルも12px未満にしない。Windowsの日本語フォールバックを指定する。
- 通常文字は背景に対して4.5:1以上、意味を持つ境界・アイコン・フォーカスは3:1以上を目標に、**状態ごとの実際の背景**で確認する。
- `Tab` 順は見た目の順序に一致させ、各画面に主領域へのスキップ手段を用意する。フォーカスは2px以上の輪郭で示し、固定ヘッダーやダイアログで隠さない。
- アイコンのみのボタンにはアクセス可能な名前を付ける。装飾アイコンは読み上げ対象から外す。入力欄には常時見えるラベルを付け、エラーは対象欄と結び付ける。
- テーマ切替・保存・検索結果更新・ウィザード遷移でフォーカス位置を予測可能にする。未保存・エラーの通知は必要な一つのライブ領域で文脈付きに知らせる。
- ドラッグに依存しないパネル表示・分割操作を用意する。動きは操作結果の説明に限り、`prefers-reduced-motion` に対応する。
- 1366×768、1440×900、1920×1080で、通常表示と125%／150%相当の文字拡大、キーボードのみの操作、未保存・保存失敗・0件・衝突を同じシナリオで確認する。
