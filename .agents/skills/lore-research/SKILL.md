# Bシナリオ実行Skill

## はじめに
1. リポジトリの `AGENTS.md`、`research/AGENTS.md`、`research/B/AGENTS.md`、`research/B/README.md` を読む。
2. `research/B/config.yaml` と `research/B/questions.md` を読む。YAMLは独自形式。存在しない自動実行機能を仮定しない。
3. `research/B/agents/` の担当指示を、工程に応じて読む。担当文書は**役割定義**であり、サブエージェント自動登録ではない。
4. Bの入力マニフェストと、禁止ファイルの非参照を確認。ブランチが異なる等の重大な条件不一致があれば停止し、報告する。

## 実行する作業
- Stage 0: 入力・権限・公開情報取得手段を確認し `00-execution/` に記録。
- Stage 1: `01-research/` に出典付きの日本語調査報告書を作成。
- Stage 2: `02-evidence/` に構造化証拠台帳と監査結果を作成。
- Stage 3: `03-analysis/` に課題・原因・既存手段・解決条件・機能候補を作成。
- Stage 4: `04-reviews/` に作家・編集者、UX、技術、安全、法務、反証のレビューを作成。
- Stage 5: `05-pdm/` に選択肢と未解決事項の整理を書く。
- Stage 6: `06-final-report/` に小学生でも追える言葉の日本語報告6本と案内READMEを作る。
- Stage 7: `07-handover/` に引継要約、入力一覧、コミットID、未検証事項を記録。

## 書式の区別（重要）
- 設定、入力台帳、証拠台帳、実行ログは安定したキー・IDで機械処理しやすく。
- `01-research/*.md` と `03-analysis/*.md` と `06-final-report/*.md` は日本語の自然な文章。見出しを短くし、冒頭に「何が分かったか」を書く。
- 専門用語は初回に一言で説明する。確定事項と推測を明示する。
- 分析の最初に機能を決めない。ユーザーの課題→成功条件→選択肢の順を守る。

## 失敗時
Webに接続できない場合は知識だけで2026年の規約・市場統計を作らず、`未取得` とし、公式URLと次の確認手順を残す。実行停止時は部分成果物と再開地点を記録する。

## 許可しない操作
`research/B/outputs/` 以外への書き込み、A/C参照、機能台帳閲覧、Git操作、Issue/PR作成、製品コード変更、未公開作品の外部送信。承認された入力ファイルからのみローカル資料を読む。
